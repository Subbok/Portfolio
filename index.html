Co zbudowałem

Kursor — system floty i rozliczeń dla PROBUS Sp. z o.o.

W produkcji

System zastępujący zestaw arkuszy Excel w firmie przewozowej: flota, serwis, rozliczenia kierowców i wycena tras w jednej aplikacji webowej. Zaprojektowany i utrzymywany przez Layershift. Pracuje produkcyjnie, na co dzień używają go pracownicy PROBUS.

▸Flota: pojazdy, przebiegi, polisy i winiety, oś czasu zdarzeń oraz interwały serwisowe (olej, przegląd, opony, klocki) liczone z konfigurowalnych reguł pojazd > typ > globalnie — bez wartości domenowych w kodzie
▸Rozliczenia kierowców: kursy, paragony, rachunki i stawki, formularze dla kierowców na telefonie oraz wydruki PDF generowane w Typst
▸Portal klienta (w przygotowaniu): firmy widzą swoje auta, grafik i rezerwacje, a biuro może ustalić, kto prowadził pojazd w danym czasie, i przypisać mandat kierowcy
▸Integracje: GPS (stany liczników, pozycje) i system wypożyczalni RCS w trybie tylko do odczytu; dane dostępowe szyfrowane w bazie
▸Cennik: wycena tras przewozów i sprawdzanie cennika, z historią wycen
▸Moduły włączane licencją. Edycja JEST dla ekip terenowych: import rozpiski tras z Excela, planowanie tygodni, checklisty, protokoły z podpisem na telefonie i PDF
▸Architektura: jedna aplikacja i jedna baza, ale twarde granice modułów — osobny schemat PostgreSQL i osobny katalog kodu na moduł, uprawnienia zamiast osobnych przypisań

Self-hosted infrastruktura serwerowa

NixOS · 24/7

Własne środowisko produkcyjne 24/7, w całości opisane kodem: host na NixOS (flake), usługi w Docker Compose, GPU NVIDIA dla ML. Chmura plików, menedżer haseł, narzędzia ML i serwery gier dla znajomych.

▸NixOS z flake’ami: konfiguracja hosta w repozytorium git, sprawdzana przez nix flake check, wdrażana jednym poleceniem, z cofnięciem do poprzedniej generacji
▸Usługi w Docker Compose uruchamiane jako jednostka systemd, zależna od zamontowanych dysków — po awarii kontenery nie startują na pustym katalogu
▸Bez otwartych portów publicznych: dostęp z internetu przez Cloudflare Tunnel, SSH tylko na klucze, fail2ban
▸GPU: NVIDIA Container Toolkit (CDI), CUDA dla CellForge, Ollama i obliczeń ML
▸Monitoring: Prometheus + Grafana, cAdvisor, eksportery hosta i GPU, alerty predykcyjne i S.M.A.R.T. na powiadomienia push
▸Niezależny drugi punkt monitoringu na osobnym urządzeniu i za osobnym tunelem — widzi awarię całego serwera
▸Kopie i odtwarzanie: btrfs z godzinnymi snapshotami (snapper), cykliczny scrub, ważne dane na osobnym dysku od odtwarzalnych
NixOS Nix flakes Docker Compose systemd Cloudflare Tunnels NVIDIA Container Toolkit Prometheus Grafana btrfs snapper fail2ban

CellForge — Notebook IDE w Rust

GitHub → Docs → GHCR →

Alternatywa dla JupyterLab zbudowana od zera w Rust + React — natywna implementacja Jupyter messaging protocol, real-time collaboration, PDF export przez Typst. Działa produkcyjnie na mojej infrastrukturze jako środowisko ML.

▸Backend: 7 crates Rust (axum + tokio + zeromq-rs) z rozdziałem odpowiedzialności — 186+ testów jednostkowych
▸Real-time collaboration przez Yjs CRDT — shared editing cel, remote cursors, per-notebook kernel sharing
▸PDF export przez Typst (~50× szybciej niż LaTeX), single binary, template-based
▸Reactive execution przez AST dependency analyzer — auto-rerun downstream cells przy zmianie zmiennej
▸Hub mode: multi-user SQLite + JWT auth, resource limits, plugin system z zipami
▸CI/CD: GitHub Actions build + push na GHCR, pre-built image z Python 3.12 + PyTorch + CUDA — deployment przez docker compose pull
Rust React 19 TypeScript Monaco Yjs CRDT ZeroMQ Typst GitHub Actions CUDA Open Source

LLM Benchmark Pipeline — Praca Magisterska

GitHub → Obroniona 2026

Wielowymiarowa ewaluacja 10 modeli LLM (6 komercyjnych + 4 lokalne) na 80 zadaniach — 800 wywołań, 4 metryki, własny pipeline w Pythonie z GPU-accelerated evaluation.

▸4 metryki: Pass@1 (unit tests), CodeBLEU (AST + dataflow), BERTScore (RoBERTa-large), G-Eval w skali 1-100 (LLM-as-a-Judge)
▸10 modeli: Claude Opus 4.6, GPT-5.2, Gemini 3.1 Pro, Grok 4, DeepSeek V3.2, KIMI K2.5 (API) + Qwen2.5 14B, Gemma3 12B, Mistral-Nemo 12B, Llama3.2 3B (lokalne przez Ollama)
▸Kluczowy wynik: modele lokalne 12-14B konkurują z komercyjnymi na zadaniach programistycznych (Gemma3 12B = 94% Pass@1, przebija 4/6 modeli API)
▸Odkrycie metodologiczne: efekt sufitowy w G-Eval skali 1-5 (5/6 modeli = 4,99-5,00), rozwiązany przez powtórną ewaluację w skali 1-100
▸Sandboxowane wykonywanie kodu z timeout protection · Master pipeline Bash z conda env management i auto-detekcją VRAM
▸GPU-accelerated ewaluacja (CUDA/PyTorch, BERTScore na RoBERTa-large) z automatycznym fallbackiem na CPU
